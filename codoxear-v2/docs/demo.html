Agent creation

The RAFT-style form follows Runtime → Provider → Model → More → Advanced. Select Pi, Codex, or Claude Code, then choose Custom API to enter an API URL, API key and model ID. Pi offers OpenAI Chat Completions, OpenAI Responses and Anthropic Messages compatibility. More includes reasoning, working directory, and supported Fast mode; Advanced includes environment variables and the Claude executable override.

Implemented in the public demo. https://codoxear.gzeek.com:8445/ — client, hubs and local launchers updated together.

Keys stay in the launched process environment. The creation form announces loading and creation, focuses invalid fields, keeps keyboard focus inside the dialog, and fits a phone viewport. Escape follows the application's existing modal rule; close with the dialog buttons.

Session resume and setup

New session includes a Start → Resume saved session choice. Select the original Computer, runtime and working directory, then load saved sessions or enter the backend session ID. Re-enter private API settings when needed. A native Codex resume restores the saved transcript and continues the conversation; the Pi and Claude native resume matrix remains open.

Review runtime onboarding and workspace trust locally on the selected Computer. Claude creation explains missing setup and keeps your form values; its startup guard preserves a message that has not been sent. Discovery now distinguishes loading and failed connections from an empty list, with reconnect and retry controls.

Workflows to try

1. Account and hub selection

Sign in as Alice, open Home demo and Work demo. Sign in as Bob in a separate browser profile: only Home demo and Home laptop are visible.

2. Multiple Computers per hub

Home demo contains Home laptop and Home workstation. Work demo has its own Work computer. Each Computer has exactly one hub.

3. Agent creation and conversation

Select a Computer, choose New agent, choose Pi, then send a message. Replies explicitly identify the scripted model.

4. Actual local tool execution

Send run demo tool. Pi executes the supplied shell command in its isolated workspace. Open proof.txt to inspect the result.

5. Full browser workspace

Use Open workspace. View Git changes, search files, read and download welcome.txt, edit and save it, upload an attachment, and search the conversation.

6. Computer-owned remote queue

Send run demo tool, then queue another prompt during its five-second tool run. Edit the queued prompt. It runs after the current turn when authorization is available.

7. Private unsent drafts

Alice and Bob can open the same Home laptop agent. Each account keeps its own unsent text.

8. Invitations and inherited retention

Alice uses Manage access to invite Bob to another computer, or remove him. Set the hub removal policy to Read-only: Bob keeps the existing transcript but cannot send or create agents. An explicit hub policy overrides the computer policy.

9. Delegated workspace files

Alice grants Bob Read files or Read and edit files in Manage access. Bob can access files only inside that Computer’s configured workspace. Removing the grant or membership removes file access.

10. Owner-only deletion and launch recovery

Delete a disposable session using the normal confirmation. Operators cannot delete. Check launch result recovers saved launch receipts without dispatching another launch; automated fault tests exercise the lost-response case.

11. Duplicate and conversation settings

Duplicate a configured agent from its sidebar card: the copy stays on its source Computer. Private launch credentials/settings must be re-entered through New session. Edit conversation name, priority and snooze; dependencies are limited to accessible agents on the same Computer.

12. Resume a saved session

Choose New session, then Start → Resume saved session. Choose the original Computer and runtime, enter its original working directory and use Find saved sessions to select a saved session, or enter its backend session ID. Re-enter private provider settings when needed. Complete runtime setup and workspace trust locally first; an already-running session should be selected instead of resumed.

13. Discovery and reconnect feedback

A fresh page shows Discovering sessions while catalogs load. An unreachable hub or Computer has an explanation, Hubs & computers and Retry discovery controls. A temporary Computer failure retains only currently authorized known sessions.

14. Claude setup and early messages

Complete Claude onboarding, workspace trust and provider/key/permissions confirmations locally on the Computer. Missing setup leaves the creation form intact with instructions. If Claude is still starting, a rejected send preserves the typed message; send it again after the native editor is ready.
