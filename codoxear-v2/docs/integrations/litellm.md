# LiteLLM model discovery

In New agent, select a Computer, runtime and configured provider, then **Discover models**. For Custom API, first enter the endpoint, key and Pi API compatibility. Discovery runs on that Computer through its authorized Hub tunnel. Computer execution access is required; revocation is checked again after the request.

The Computer reads `/v1/models` with that provider key and joins `/model_group/info` by exact model ID. Group metadata cannot add models missing from the caller-visible listing. Optional `supported_reasoning_efforts` and `supports_reasoning` retain their meaning: null or absent levels are unknown; an explicit empty list is distinct. Parameter names from `/utils/supported_openai_params` are not reasoning-level values.

These are advertised capabilities, not a health check or independently tested provider behavior. The form separately identifies compatible runtime requests. Pi OpenAI-compatible discovered definitions can preserve `none`, `xhigh` and `max`: `none` uses an explicit internal Off-to-wire-`none` mapping, while the extended levels use identity mappings. Installed-SDK wire regressions verify those transformations. For Pi Anthropic Messages, per-session definitions explicitly enable the installed SDK’s adaptive-thinking compatibility and identity effort map. Requests send `thinking.type: adaptive` and exact `output_config.effort` for supported categorical levels, including `max`; no model-name inference or effort-to-budget downgrade is used. `none` follows the explicit disabled-thinking branch. Unsupported advertised values remain visible but disabled with a protocol-specific explanation. Unknown model metadata does not justify a fabricated effort list or silently lowering a selected level.

Creation rechecks the selected discovered model with the same provider credentials. A model absent from Pi's local catalog receives a private, per-session definition; configured endpoint/key and per-model API overrides are retained. Global model files are not modified. Closing the dialog or changing Computer, runtime, provider, endpoint, key or API compatibility cancels/invalidate discovery. Keys are never returned in catalog results, browser storage or diagnostic messages. Response size/model counts and request time are bounded; credential-bearing redirects are not followed.

The owner's read-only investigation reports LiteLLM 1.103.2 on the external gateway and a CPA catalog filter that omits `supported_reasoning_efforts`. Codoxear preserves this field when the caller receives it. The gateway's `overlays/runtime/custom/cpa_catalog.py` is not present in this checkout or current LXC. Its administrator should preserve the field in the protected catalog allowlist without expanding model visibility or borrowing administrator credentials. Until then, omitted fields remain unknown in Codoxear. Add metadata for an unknown model only after verifying its actual provider/protocol behavior; a familiar model name or `supports_reasoning: true` alone is insufficient.
