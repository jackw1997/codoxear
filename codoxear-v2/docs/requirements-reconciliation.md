The current conversation requires a self-contained Linux TypeScript migration with native PTYs, independent Computer/Hub/Client components, usable mobile browser flows, and preservation of existing v2 functions and the user's running legacy agents. Earlier designs remain useful evidence, but their superseded implementation prescriptions do not override these requirements. This audit records the decisions before the next implementation slices; it does not claim those slices have already passed acceptance.

## Corrected acceptance interpretation

The current records accept a Linux native TypeScript migration, not the complete design. They report a fresh v2-only production build, 160/160 Docker TypeScript tests without skips and 46 generic browser checks, together with additional targeted installed-CLI/provider/workspace evidence. This audit did not rerun runtime or browser tests; it reviewed local documents and the declared component/build boundaries. Historical 125 TypeScript plus 64 Python counts in `agentCreationUpdate` are explicitly legacy-backed and do not form native v2 evidence. The older native snapshot of 157 tests is valid historical evidence; 160 is the later PR-review snapshot. Counts from different suites/runs must not be added into one acceptance claim.

Already implemented/accepted slices include independently runnable components; independent Hub authority; native detached PTYs and incarnation fencing; three-runtime creation/private-provider routing; Pi tool execution and terminal import; native Codex/Claude create/send/transcript/reload; trusted Codex resume; remote queue, private drafts and launch receipts; file/Git/media owner flows and secure Linux workspace access; delegated single-workspace read/write/revocation; selective agent sharing; access-loss/stream fencing; invitation targets; discovery/retry states; conversation metadata and bounded unattended idle behavior. Each remains subject to the precise evidence scope in the registers.
