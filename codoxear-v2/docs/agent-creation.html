Agent creation

Choose a computer, then Pi, Codex, or Claude Code. The form follows RAFT’s Runtime → Provider → Model layout. Choose “Configured on computer” to use existing credentials, or “Custom API” to enter an API URL, API key, and private model ID directly.

Custom endpoints require a valid HTTP(S) URL, an API key, and a model ID. Keys and environment values use password inputs. Switching providers clears the URL/key; switching runtimes or computers resets incompatible fields. Environment variables have add/remove rows and reject duplicate names. Computer defaults remain available when its catalog cannot be loaded.

The same creation form serves the independent client, account UI, and account workspace. Provider settings travel through the hub and Computer tunnel into the native launcher. Credentials are passed in each child process’s environment; they are not written to browser storage, hub agent records, the launch journal, or global CLI configuration. Claude custom providers remove inherited OAuth and cloud routing unless explicitly supplied in Advanced. Computer owners may supply launch settings; shared operators retain default creation.

Use the self-contained TypeScript Computer to configure provider settings. Its native runtime advertises provider-launch support and starts detached Node PTY brokers. Python and the original Codoxear package are not required.

Design reference

The control structure follows Botiverse’s RAFT runtime form and model-dependent reasoning selection, inspected at release 05f7d8f (v1.13.0-source.1). Codoxear’s implementation uses its own Computer catalog and launch contracts.

Verification

Run node --import tsx scripts/browser-agent-creation.mjs inside the built Docker verification environment. It exercises the actual independent client and service worker, the shared form, outgoing launch payloads, stale catalog responses, and all three mobile layouts. The upstream hub is a controlled fixture. Native CLI verification uses local scripted gateways and disposable credentials; it proves endpoint/key/model routing, not live inference or provider login.
